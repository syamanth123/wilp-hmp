## 1. AI features behind one switch (`AI_FEATURES_ENABLED`, default off)

Single helper `apps/web/src/lib/features.ts` → `aiFeaturesEnabled()` (exists). When off:

**Hidden in the UI**

- Faculty: AI quality panel in both places (editable and submitted states); `QualityReportCard`;
  legacy editor "Generate with AI" button and dialog; structured editor AI draft (done in step 2).
- HOG request page: `recommendFaculty()` is **not called** during render; the "AI suggestions"
  list is not shown (`allocation-panel.tsx` gets `recommendation = null`).
- `QualityReportCard` also on IC, HOG and PC request pages.
- Admin: "AI Metrics" tab and the overview's "AI metrics" quick link removed; `/admin/ai-metrics`
  returns 404; the "ai queue" card on Queues hidden; the "AI provider" row on the overview hidden.
- Faculty dashboard checklist: the "Bloom's coverage" item (needs an AI report) is dropped, so the
  checklist can reach 5/5.

**Refused on the server** (each `'use server'` function returns
`{ error: 'This feature is switched off.' }` before doing anything): `runQualityCheckAction`,
`generateAiDraftAction`, `applyAiDraftAction`, `generateStructuredAiDraftAction`,
`applyStructuredAiDraftAction`, `regenerateRecommendationAction`, `runReEmbedAction`. The on-submit
quality report in `submitForReviewAction` / `submitStructuredForReviewAction` is skipped (the
submit itself still works). Queue actions refuse `queue: 'ai'`. The worker's `processAiJob` drops
AI jobs when off.

**Not AI, kept and relabelled:** fetching last year's handout. Start-editing card text →
"**Start from last year's handout** — the editor opens with the most recent approved handout for
this course (or a blank one if there is none). Review it and adjust for this semester."
Banner titles → "Started from last year's handout" / "Started from an approved past handout" /
"Started from a blank handout"; reset button → "Start from a blank handout instead".

**Plumbing:** add `AI_FEATURES_ENABLED` to `turbo.json` pass-through, `.env.example`,
`apps/web/.env.production.template`, `deploy/DEPLOYMENT_CHECKLIST.md`. Nothing is deleted;
setting it to `true` restores everything.

**Tests:** unit tests for `aiFeaturesEnabled()` and for each guarded action in both settings;
`processors.test.ts` covers both; e2e `m8-ai-layer.spec.ts` and `ai-cost-dashboard.spec.ts` become
"AI hidden" checks (suggestions list absent, `/admin/ai-metrics` 404, no AI tab); m9's queue check
no longer expects an "ai queue" card when off.

## 2. Bulk tools for HOG and PC

The role tab menus are flat lists, so each gets one new tab **Bulk tools** opening a hub page
(`/hog/bulk`, `/pc/bulk`) of cards. Each card: title, one plain sentence, **Open**,
**Download template**, and "How to fill the template" help (column names in code style only there).

| Role | Card                              | Opens                         | Sentence                                                                           |
| ---- | --------------------------------- | ----------------------------- | ---------------------------------------------------------------------------------- |
| HOG  | Bulk allocate faculty (upload)    | `/hog/requests/bulk-allocate` | Allocate faculty and an SME to many new requests at once from one spreadsheet.     |
| HOG  | Bulk review handouts              | `/hog/bulk-review`            | Give final approval, request rework or reject many handouts at once.               |
| PC   | Bulk confirm allocations (upload) | `/pc/allocation-review`       | Confirm or send back many faculty allocations at once. (Today nothing links here.) |
| PC   | Bulk review handouts              | `/pc/bulk-review`             | Approve and forward, or request rework on, many submitted handouts at once.        |

Each bulk page gets a "← Back to dashboard" link. Verified already: the PC allocation template's
columns (`request_reference, action, comment`) and actions (`pc_confirm_allocation`,
`pc_reject_allocation`) match its validator exactly. Small fixes: an empty or header-only upload
says "The file has no rows" instead of "0 applied"; the help mentions the 2,000-character comment
limit and that action names must match exactly. Proof: one e2e per page uploading a 1–2 row CSV
through the hub (HOG bulk review and PC allocation review have none today).
