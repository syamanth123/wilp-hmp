# Course Dibba → faculty schedule: 5-minute demo script

Runs on the laptop against the LOCAL database loaded by `pnpm --filter @hmp/db seed:dibba-demo`
(real 2025 Course Dibba, real 2024 faculty sheet, sample class times and exam dates). Nothing
here touches the pilot server. App: http://localhost:3000. Every password is `password`.

Wording to use in the room: "slot", "class time", "exam date". Whether SL1–SL8 are class slots,
exam slots or both is still unconfirmed with the Instruction Cell; the screens are neutral.

The loader prints three logins at the end of its run (the richest schedules; the first has a clash).
`faculty@hmp.local` (seeded on-campus faculty) also works: its courses come from HMP handout assignments AND the sheet.
`pc@hmp.local` sees the same overview under **Schedule**.

If asked:

- "Where does the clash come from?" — same person, same slot, two different courses after
  merging cross-listed codes; the 2025 Dibba × 2024 sheet has 25 of them.
- "Does this change the live site?" — no; the pilot is untouched until a deliberate deploy
  (RDS snapshot → `soffice --version` → `prisma migrate deploy`).
- "Can faculty see each other's schedules?" — no; the schedule query is keyed by the signed-in
  user, and a test proves user B never sees user A's courses.
